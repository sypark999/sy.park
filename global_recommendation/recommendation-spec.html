1. 배경 및 목적

배경

AS-IS
  • 매장 탐색 전후 타 매장을 자연스럽게 추천할 수 있는 마케팅 구좌가 부족함
  • 1차 탐색 이후 체류·탐색 유도 불가 — 풀예약 매장에서 유저가 바로 이탈
TO-BE
  • 매장 탐색 시 유사 / 인기 매장 추천 구좌 신설
  • 탐색 흐름 내에서 2차 클릭, 추가 예약을 유도

목적

매장 상세페이지 및 마이다이닝에 매장 추천 기능을 추가하여 유저의 탐색 경험을 강화하고, 전환율 개선 및 예약 수 증가를 유도한다.

  • 매장 상세: 풀예약/인기 매장에서 유사 매장을 추천하여 이탈 방지 → 예약 전환
  • 마이다이닝: 개인화 추천으로 재방문 유저의 추가 탐색·예약 유도

2. 분석 및 영향 사항

노출 위치 및 조건

위치노출 조건추천 타이틀비고
매장 상세페이지풀예약 OR 인기매장"If You Like [매장명]"예약 섹션 하단, Reserve 버튼 위
마이다이닝항상 노출"Top picks for Name" / "Popular near you"예약 카드 하단 (없으면 바로 노출)

매장 상세페이지

  • 풀예약: 선택 가능한 예약 슬롯이 없는 매장
  • 인기매장: 수동 리스트업 (운영 태깅)
  • 두 조건은 OR — 둘 중 하나만 해당되면 추천 노출
  • 예약 가능한 날짜가 있는 일반 매장에서는 추천 미노출
  • 1-1. 모든 날짜에 예약 가능 슬롯이 없는 경우: Find available time 하단 추천 매장 노출
  • 1-2. 날짜 선택 후 예약 가능 슬롯이 없는 경우: 해당 날짜의 슬롯이 열려 있는 추천 매장 노출

마이다이닝

  • 예약 예정이 있는 유저: 예약 카드 아래에 추천 섹션
  • 예약 예정이 없는 유저: 빈 상태 + 추천 섹션 바로 노출
  • "near you"의 범위는 한국 전체
  • 하단 설명: "From your recent interests including [매장명]" (예약/웨이팅 내역 우선)
  • ref: Spotify "Made for you", Netflix "Top picks for [Name]", Google Maps "Popular nearby", Instagram "Popular near you"

추천 카드 UI

  • 3개 고정 노출 (가로 스크롤 없음)
  • 이미지 (1:1 정사각형 예상, 디자이너 확정 예정) + 매장명 + Cuisine + 평점
  • 탭 → 해당 매장 상세페이지로 이동
  • 중복 처리: 추천 3개 간 중복 제외, 현재 보고 있는 매장과 동일 매장 제외

Phase 1 하드코딩 (현재 기획)

데이터 소스

  • 매장 상세페이지: 국내앱 기존 데이터 활용하여 세팅
  • 마이다이닝: 수동 큐레이션

운영

  • 초기 1회 세팅 후 필요 시 수동 변경
  • 운영 담당: 기획자 (박송연)

제약사항

  • 예약 마감 매장도 그냥 노출 (실시간 필터링 불가)
  • 모든 유저에게 동일한 추천 노출 (개인화 없음)
  • 추천 새로고침 없음 (재방문 시 동일 3개)

Phase 2 대비 고려사항

  • API 구조를 Phase 2 추천 로직 전환에 대비하여 설계
  • 프론트엔드 카드 컴포넌트는 Phase 1/2 동일하게 사용 가능하도록

Phase 2 추천 로직 (추후 개발)

케이스 분기

우선순위조건노출 구성
1예약/웨이팅 내역 + 최근 본 매장 둘 다 있음최근 본 매장 1 + 최근 본 기준 유사 1 + 예약 기준 유사 1
2예약/웨이팅 내역만 있음가장 최근 예약/웨이팅 기준 유사 매장 3

  • 예약/웨이팅 내역: 가장 최근에 한 예약/웨이팅 1개
  • "최근"의 시간 범위: 데이터 저장 정책 확인 필요 TBD

음식 종류 카테고리 매칭 (40점 만점)

카테고리는 1 → 2 → 3단계로 갈수록 세분화됨.

일치 레벨점수비율
3단계 일치 (가장 세분화)40점100%
2단계 일치28점70%
1단계 일치12점30%
불일치0점0%

스코어링 예시

기준 매장: 이탈리안 / 강남 / 5만원대 / 4.5점

후보 A: 이탈리안 / 강남 / 3만원대 / 4.3점
→ 음식 40 + 위치 25 + 가격 10 + 평점 12 = 87점

후보 B: 한식 / 강남 / 5만원대 / 4.7점
→ 음식 0 + 위치 25 + 가격 20 + 평점 15 = 60점

후보 C: 이탈리안 / 홍대 / 5만원대 / 4.0점
→ 음식 40 + 위치 0 + 가격 20 + 평점 10 = 70점

결과: A(87) > C(70) > B(60) 순 추천

예약 마감 매장 처리

  • Phase 2에서는 예약 가능 매장만 필터
  • 하드코딩 3개 중 마감 발생 시 백업 풀에서 자동 대체

중복 처리

  • 최근 본 매장 = 예약한 매장이 같은 경우 → 슬롯 1개로 합치고 유사 매장으로 채움
  • 추천 매장이 이미 본/예약한 매장과 겹치면 제외

가중치 튜닝

  • 초기 비율로 런칭 후 클릭률/전환율 데이터 기반으로 조정
  • 가중치 비율은 config로 분리하여 서버 배포 없이 변경 가능하도록 권장
