1. 배경 및 목적

배경

캐치테이블 글로벌은 현재 "지역 + 음식 + 맛집" 키워드군에서 오가닉 검색 유입을 확보하지 못하고 있다.

  • AS-IS: 현재 해당 키워드군의 Search Console 기준 월 노출수 ___건, 클릭수 ___건으로, 사실상 검색 유입이 발생하지 않는 상태
  • 원인: 기존 /explore 지도 페이지는 필터링 기능은 갖추고 있으나, ① 텍스트 콘텐츠 부족(thin content), ② 쿼리 파라미터 URL 구조, ③ 검색 의도(리스트형)와 포맷 불일치로 인해 검색엔진 랭킹에 구조적 한계가 있음
  • 시장 현황: "강남 오마카세", "홍대 한식" 등 타겟 키워드의 SERP 상위 결과는 거의 전부 리스트형 콘텐츠. 트립어드바이저(프로그래매틱 SEO), 망고플레이트(/top_lists/), 다이닝코드 등 경쟁 플랫폼이 이미 이 포맷으로 해당 키워드군을 선점 중

목적

"지역 × 음식" 조합별 전용 리스트 페이지를 생성하여, 검색 유저의 의도에 부합하는 포맷으로 오가닉 유입을 확보하고, 리스트 → 예약이라는 직관적 전환 동선을 구축한다.

캐치테이블은 타 리뷰 플랫폼 대비 실시간 예약 기능이라는 차별점이 있어, 검색 유입을 예약 전환까지 직접 연결할 수 있음.

데이터 매핑 로직

  1. 지역(56개) / 음식(20개) 단일 리스트 생성
  2. 56 × 20 = 1,120개 조합 중 매장 5개 이상인 조합만 필터 → 유효 조합 수: ___개
